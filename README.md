# PMLDL Assignment 1: Deployment

An automated MLOps pipeline that processes data, trains a machine learning
model, and deploys it as a REST API together with a web application.
The model predicts Titanic passenger survival.

## Repository Structure

├── src
│ ├── datasets/ # data download and preprocessing scripts
│ ├── models/ # feature engineering and model training
│ └── deployment/
│ ├── api/ # FastAPI model serving app + Dockerfile
│ ├── app/ # Streamlit web app + Dockerfile
│ └── docker-compose.yml
├── data
│ ├── raw/ # raw downloaded dataset (DVC-tracked)
│ └── processed/ # train/test splits (DVC-tracked)
├── models/ # trained model file (DVC-tracked)
├── scripts/
│ └── run_pipeline.ps1 # full pipeline runner (used for scheduling)
├── dvc.yaml # DVC pipeline stages
├── metrics.json # latest test metrics
└── requirements.txt

## Running the Pipeline

### Option 1: Run everything with DVC

This runs data download, data preparation, and model training in the
correct order, skipping stages whose inputs have not changed.

```bash
dvc repro
```

Outputs:
- `data/raw/titanic.csv` — raw dataset
- `data/processed/train.csv`, `data/processed/test.csv` — cleaned and split data
- `models/model.joblib` — trained model
- `metrics.json` — test metrics (accuracy, precision, recall, f1)

View metrics:

```bash
dvc metrics show
```

### Option 2: Run individual stages manually

```bash
python src/datasets/download_data.py
python src/datasets/prepare_data.py
python src/models/train_model.py
```

## Deploying the API and the App

```bash
cd src/deployment
docker-compose up --build
```

This builds and starts two containers:
- **API** (FastAPI) — serves predictions at `http://localhost:8000`.
  Interactive docs: `http://localhost:8000/docs`
- **App** (Streamlit) — web interface at `http://localhost:8501`

Stop the containers:

```bash
docker-compose down
```

## Full Automated Pipeline

`scripts/run_pipeline.ps1` runs the full pipeline end to end: DVC pipeline
(data + training), then rebuilds and restarts the Docker containers so the
API always serves the latest trained model.

Run it manually:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_pipeline.ps1
```

### Scheduling (Windows Task Scheduler)

The pipeline is scheduled to run automatically every 5 minutes using
Windows Task Scheduler. To set it up (run PowerShell as Administrator):

```powershell
$action = New-ScheduledTaskAction -Execute "powershell.exe" -Argument '-ExecutionPolicy Bypass -File "<full path to>\scripts\run_pipeline.ps1"'
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Minutes 5) -RepetitionDuration (New-TimeSpan -Days 3650)
Register-ScheduledTask -TaskName "MLPipeline" -Action $action -Trigger $trigger -Description "Retrain model and redeploy every 5 minutes"
```

Check status:

```powershell
Get-ScheduledTaskInfo -TaskName "MLPipeline"
```

Disable/enable:

```powershell
Disable-ScheduledTask -TaskName "MLPipeline"
Enable-ScheduledTask -TaskName "MLPipeline"
```

## Experiment Tracking

Model training is tracked with MLflow. Tracking data is stored locally in
`mlruns/` (not committed to the repository — it is regenerated on every
pipeline run). To view the experiment dashboard:

```bash
mlflow ui
```

Then open `http://127.0.0.1:5000`.

## Notes

- The dataset used is Titanic (binary classification: survived or not).
